## Loose ends — real, named, not smoothed over

### 1. Worker bbox filter is committed but NOT deployed
`b748bbf` adds server-side bounding-box filtering to the Worker. It is **not live** —
the Cloudflare quick-edit editor refused three scripted paste attempts (`Ctrl+A`
kept selecting the page rather than the Monaco iframe, which is cross-origin and
can't be scripted into).

**Why it matters:** `roadConditions` returns **~3.6 MB** statewide (dense LineString
geometry). That's unacceptable over cell data, which is why the roadConditions
layer is *not yet added*. `incidents` is only ~10 KB, so tonight's feature is
unaffected.

**To deploy:** open the Worker's *Edit code*, select all, paste the current
`worker/cotrip-proxy.js`, Deploy. A manual `Ctrl+V` is a real user gesture and
will likely work where automation didn't.

### 2. `fetchMinerals` times out on the desktop page
Throws `TypeError: Failed to fetch`. **Pre-existing, not from tonight.** Checked:
the USGS endpoint is up (HTTP 200) and sends `Access-Control-Allow-Origin: *`, but
takes **~12 seconds**. So it's a timeout, not an outage. Fix is probably an
explicit `AbortController` timeout + a smaller WFS query, not a new data source.

### 3. Three camera locations still have no real CDOT coverage
Villa Grove, Cumbres Pass, North Pass/Cochetopa — kept visible and honestly
labeled rather than silently removed. Poncha Pass is a real camera that was
offline; its image path was deliberately **left empty rather than guessed**. If
CDOT brings it back, re-check `cotrip.org/list/cameras` and fill in the real path.

### 4. Cloudflare dashboard tab may hold unsaved editor changes
From the failed paste attempts. **Don't hit Deploy in it** — close and discard.

## Next steps, roughly in value order

### A. Road surface conditions from RWIS (`weatherStations`) — highest value
Already in the subscription, already proxied, **not yet used**. CDOT's roadside
weather stations report **road surface temperature and condition** — which is the
actual question in winter: not "is it snowing" but "is US 160 over La Veta iced".
This is the single most valuable unused feed for someone who actually drives these
passes.

### B. `roadConditions` layer — gated on deploying the bbox filter (loose end 1)
Statewide winter driving conditions per segment. Deploy the filter first, then add
as a line overlay, mobile included.

### C. `plannedEvents` — construction and closures
Lower urgency than incidents but genuinely useful for trip planning, especially the
CO 17 paving work.

### D. Correlate cameras with incidents
When an incident is near a camera, offer that camera's live image in the incident
inspector. Both datasets are already loaded — this is pure UI, no new fetching, and
turns "there's a crash on US 160" into "here's what it looks like."

### E. Alert quality pass
Right now any closure raises an alert. Worth weighting by proximity to Antonito and
by whether it's on a route you actually use (US 285, US 160, CO 17) rather than
treating a Front Range closure the same as a local one.

## Standing lessons this app keeps teaching

- **A 200 is not a success.** Three separate times tonight a success status meant
  something other than what it looked like: a redirect stub, a GraphQL query that
  returns a clean `0` for a *bogus* layer name, and an Angular SPA shell served for
  every path including `/api/v1/incidents`. Check the body, not the status.
- **Absence of data must announce itself.** The dead NOAA endpoint hid behind
  `if (res.ok)` with no `else`. Every guarded network call needs a failure branch
  that at minimum warns, plus a payload-shape guard.
- **Test the path that doesn't run.** With zero local incidents, the marker-drawing
  code would never have executed and would have shipped broken. Exercising it
  against real statewide data found a genuine bug: CDOT returns **Point AND
  MultiPoint**, and the first filter silently dropped every MultiPoint — i.e.
  exactly the segment-spanning closures that matter most.
- **"Saved" is not "deployed."** In Cloudflare, saving a secret creates a *version*;
  the running deployment keeps its old bindings until the new version is promoted.
